# Flower Studio 2.0 Schema 约束评审

状态：2026-11-05 草案评审；尚未替换运行中的 Schema 或执行迁移。评审对象为 `flower-wms-system/prisma/schema.v2.draft.prisma`。

## 已在 Prisma 草案中表达

| 规则 | 当前表达 |
|---|---|
| 默认 SKU 必须属于同一商品 | `Product.defaultSku` 使用 `(Product.id, defaultSkuId) → (ProductSku.productId, id)` 复合关系；商品初建时可为空，上架前必须设置。 |
| 打样执行选中的推荐方案必须属于同一计划 | `SamplePlanExecution` 使用 `(planId, selectedRunId) → (SamplePlanRun.planId, id)` 复合关系。 |
| 物料、商品、供应商编码不跨租户冲突 | 各根实体使用 `(tenantId, code)` 唯一约束。 |
| 同批次同位置只有一条余额 | `BatchBalance(batchId, locationId)` 唯一。 |
| 支付、退款和库存流水避免重复回调 | 各事实记录有唯一 `idempotencyKey`。 |

## 初始 SQL migration 必须补强

Prisma 校验关系形状，但无法单独保证下列跨行或数值不变量。

1. `CHECK`：所有库存、预留、采购分配和验收数量非负；`frozenQty <= onHandQty`；SKU 价格与支付金额非负；整枝、整块、整卷物料数量须满足其 `quantityScale=0` 的规则。最后一项跨表，需应用层事务校验或数据库触发器。
2. 外键归属：订单的 `storeId` 必须属于 `tenantId`；订单项 SKU、配方物料、采购供应商、验收物料、批次位置、打样来源 SKU 等不得跨租户或跨门店引用。能使用复合外键的地方优先在迁移中加约束，动态业务关系由服务层集中校验。
3. 默认 SKU 上架规则：`defaultSkuId` 非空且 SKU 启用；在售商品至少一个启用 SKU。停用默认 SKU 前先重选；停用最后一个启用 SKU 前先下架。这些是跨行状态规则，必须事务处理。
4. 成本及历史：已发布配方版本、已结账成本快照、库存流水、支付与退款事实只追加或以新记录修正；数据库权限和服务 API 都不得提供直接覆盖路径。

## 必须用事务和并发控制保证

### 顾客订单与打样共享库存

同一批次的可分配量计算为 `onHandQty - frozenQty - 顾客有效预留 - 打样有效预留`。待支付有效锁定按物料另计，不能与正式预留重复计算。预留动作在同一数据库事务中锁定相关余额行、检查所有有效占用、写入预留及状态；失败则整笔回滚。多批次分配按稳定顺序加锁以减少死锁。已确认顾客订单预留不被后来的打样操作挪用。

### 在途供应

只有供应商已确认的采购行可创建 `FutureSupplyAllocation`。同一采购行的有效未来分配总量不得超过已确认且未验收的基础单位数量；到货、取消或供应商变更时，在同一事务中重算受影响订单。采购建议不形成保障。

### 支付转换

待支付订单支付成功时，先以幂等键确认回调，再在同一事务中将有效物料锁定转为正式需求和预留。若现货与确认在途仍不足，订单保留已付款事实并显示供应风险，不能标记为可制作。过期、取消和回调并发须通过订单版本或条件更新确保只生效一次。

### 打样执行

批准方案时重新评估现货，只预留首件样品所需批次。拆解后的实际可复用花材经员工确认后才供下一步计算。执行计划选定的 Run 必须属于同一计划，批准后不能静默改选。完成打样或取消时释放剩余预留；已进入制作区的花材按实际验收处置。

## 本轮发现并修正

- 原 `defaultSkuId` 仅引用 SKU ID，不能保证归属同一商品；已改为复合关系。
- 原打样执行的 `selectedRunId` 是裸字符串，可能引用别的计划或不存在的结果；已改为复合关系。
