# Flower Studio 2.0 业务规则与领域模型设计稿

状态：已讨论规则的设计基线；供后续 Prisma Schema、服务和真实门店试用验证。本文描述 2.0 目标，不代表旧代码已经实现。

## 1. 目标和范围

面向花店统一管理多渠道订单、商品与配方、花材及耗材、采购、批次库存、制作、交付、损耗和成本。首版订单入口为微信小程序与后台人工录单。采用 Next.js、PostgreSQL、Prisma 的模块化单体；当前单一经营主体和门店，保留未来多租户、多门店扩展的归属边界。现有系统未正式上线，没有真实历史数据迁移约束。

产品原则：系统自动记录可从既有信息推导的常规事实；员工只处理差异、异常及真正需要作出承诺的判断。正常订单不得因未分配负责人、未逐项领料、未填写工时或未上传照片而卡住。以下自动化规则须在真实试用中验证并调整。

## 2. 组织与核心对象

- `Tenant`：经营主体及数据归属。当前只有默认主体；业务数据通过服务端上下文确定归属，预留未来隔离接口。
- `Store`：订单、制作和交付的门店归属。当前只有默认门店，不展示切换器。
- `InventoryLocation`：仓库、制作区等物理位置。正常制作的位置流转由系统处理。
- `Material`：采购、配方、库存共用的唯一物料身份，包含品种、颜色、品质等级、规格和基础库存单位。
- `Product` / `ProductSku`：面向顾客的商品及独立定价、下单的销售规格。每个在售商品至少一个 SKU。
- `Recipe` / `RecipeVersion`：SKU 的标准制作方案及不可覆盖的已发布版本。
- `InventoryBatch`：物料在一次验收或入库后形成的可追踪库存；数量按物料、批次、位置管理。
- `PurchaseOrder` / `GoodsReceipt`：采购承诺与每次实际到货验收分离。
- `Order` / `OrderItem`：商业交易及商品或定制花礼明细，关联物料需求、预留、制作和交付。

关系主线：订单项锁定 SKU 与配方版本（或定制物料计划）→ 展开物料需求 → 批次预留或采购建议 → 到货验收形成批次 → 制作消耗 → 实际成本。采购明细可关联多个订单需求，追踪延迟影响。

## 3. 物料身份、等级和单位

花材的品种、颜色和品质等级构成可区分物料；长度是等级判定元素，不默认单独建物料。供应商、采购价和本次到货时间属于采购与批次信息。同规格物料可由多个供应商供应。不同规格的花泥分别建档，按整数“块”库存。不同规格丝带、胶带分别建档，按整“卷”入库和领用；不逐单记录长度，也不逐单预留整卷。

每个物料有基础库存单位。花材可以按扎、把、箱采购，但验收时按实际枝数入库，采购明细保留当次采购单位及实际换算，不能假定全局固定比例。验收发现采购 A 级花材中部分仅符合 B 级时，可将可用部分降级入 B 级物料的批次；必须记录降级数量、原因和最终成本。拒收品不进入可用库存。B 级不得自动替代订单配方中的 A 级，需人工确认；影响客户可感知品质时还需客户确认。

## 4. 商品、定制与配方版本

尺寸、规模或固定价格档位等稳定销售差异建立独立 SKU。后台可创建不属于标准商品的定制订单项；草稿可暂缺报价和物料计划，但履约确认前必须补齐。定制方案不会自动发布为商品。标准订单的临时调整只改变订单方案，不覆盖标准配方。

商品创建和编辑页维护所属 SKU 列表：可从同一商品的草稿 SKU 中选择或新建 SKU，逐个设置售价、规格和配方，并指定一个默认 SKU。默认 SKU 必须属于该商品且处于可售状态；商品上架时至少有一个可售 SKU。顾客进入商品详情时预选默认 SKU，仍可主动选择其他可售 SKU。切换默认 SKU 或修改售价不改变既有订单的商品及价格快照。

若默认 SKU 暂时售罄，前台优先预选该商品第一个有货且可售的 SKU，不自动改动后台默认设置；所有 SKU 售罄时继续展示商品但禁用购买。已上架商品可停用 SKU，历史订单引用保留；停用最后一个可售 SKU 前须先下架商品，停用默认 SKU 前须另选默认 SKU。样品转 SKU 时图片和说明可复制到草稿供编辑，不自动发布。

每个 SKU 同时只有一个默认生效配方版本，历史版本保留。改变物料或等级、用量、包装、替代规则、标准损耗，或影响制作与客户承诺的说明，应产生新版本。纯内部文字勘误可留痕修订。版本先草稿、后发布，可设未来生效时间；已被订单使用的版本不可覆盖或物理删除。

小程序提交待支付订单时记录报价依据的候选配方版本，支付时校验并确认；若期间发生影响报价或承诺的变化，要求重新确认。后台草稿可更新，履约确认时锁定。已确认订单不随新版本发布而变化。配方行设置标准用量及可选容差，需求与采购使用明确的计划用量。整卷耗材可列制作说明和每件预计成本，不以小数卷逐单预留。替代候选仅供提示，跨等级替代人工决定。

## 5. 订单、供应与修改

订单至少区分商业、供应、制作、交付四个状态维度；收付款及退款另有记录，支持部分退款。后台人工订单可为草稿或待客户确认；小程序普通订单从提交进入待支付。`createdVia` 表示进入系统的方式，`sourceChannel` 表示客户来源。待支付订单短时锁定可售能力，不指定批次，超时或取消自动释放。支付成功或授权人工确认履约时形成正式物料需求，并自动尝试批次预留。

缺货仍可记录订单请求；现货、确认在途或符合明确预约规则时可形成履约承诺。待采购、待替代、部分保障或无法履约的订单保留供应风险，不得显示为已获供应保障。确认在途需校验预计到货早于物料就绪时间及未分配数量；尚未下单的采购可能性只生成建议。小程序普通订单不能在供应可行性未知时正常收款；预约销售需有明确提前量和可采购规则。客户可感知替换须客户确认。

订单确认后修改商品、数量、配方或交付时间，作为订单变更留痕；在同一事务中先验证新方案，再原子调整需求与预留，失败则保留原方案。制作开始后涉及物料或规格的变更转人工协调。联系方式、贺卡等修改按实际影响处理。已支付改价保留原支付记录，差额形成补款或退款。已交付事实通过售后或更正记录处理，不直接覆盖。

## 6. 库存、批次与自动制作

批次可用量＝该位置实存量－有效预留量－冻结量；已领至制作区的数量不属于仓库可用量。预留不改变实存；领料或自动位置流转改变位置；最终使用、损耗、退回分别结转。库存不允许负数。入库、位置流转、退料、消耗、损耗和盘点调整留不可覆盖的流水；预留与释放有独立记录。

易损花材有可靠最晚可用时间时按 FEFO 分配，否则按 FIFO；冻结、等级不符或制作前可能失效的批次不可分配。一项需求可拆分多个批次。员工可更换推荐批次，但需重新校验并记录原因。盘点差异通过调整流水处理；若影响已有预留，标记相关订单供应风险。

订单确认后系统自动创建制作待办，无需预先分配负责人。开始操作时自动记录操作人。正常制作可直接开始，无需先点领料；系统基于订单计划和推荐批次自动处理默认流转。完成时若无差异，按计划结转；替换、补用、损耗、退料等才需员工记录。库存流转应能处理“未点开始而直接完成”的操作，并在结转前重新校验数量和批次，不能生成负库存或静默错扣。普通任务无需强制逐项质检或拍照；特定定制、客户要求或异常场景可配置检查。返工保留原事实，追加用料与成本。

## 7. 采购、验收与损耗

系统汇总缺料及安全库存生成采购建议，预填采购单；员工确认向供应商发出的采购承诺。多个订单可合并采购，保留需求分配关系。紧急现采可直接入库，但须记录来源、供应商、数量、成本和原因。采购明细可分多次到货，每次独立验收；短装可待补或关闭，超收需确认。每次到货按实际等级拆分批次，记录合格、降级、拒收和最终成本。到货后自动尝试满足相关订单需求，仍缺货者保持风险。到货延期自动提示受影响订单。

能明确归因于订单的额外制作或配送损耗关联订单；正常修剪按配方预计损耗处理，明显超出才记录异常。养护、临期报废属于门店期间损耗；供应商责任单列，便于追偿。普通损耗可快速记录，超过阈值或盘点差异提醒复核，不阻断制作。批次暂无法确认时保留待核实异常，不能任意扣错批次。

## 8. 成本和经营口径

标准成本用于定价，计划成本用于接单判断，实际成本用于完成后的利润分析。订单实际成本包含批次花材、逐件包装与花泥、可归因损耗、配送及平台费用；采购运费计入对应批次。人工首版按商品或制作类型估算，无需计时。丝带、胶带按 SKU 或定制方案计每件预计耗材成本，整卷领用用于门店库存控制，报表不得重复计费。日常无法归因的损耗不逐单分摊，在门店经营结果单列。

到货可暂估批次成本；价格、折价和共同费用确定后形成最终成本，共同费用默认按验收金额比例分摊，允许有原因的人工调整。未结账订单更新成本；已结账订单保留快照，以成本调整记录差额。实际配送成本晚于订单时先暂估。退款保留收入、消耗与成本历史，另记退款和售后费用；退款不自动物理回库。

## 9. 门店、权限、配送与产能

物料、商品、配方、供应商归经营主体；订单、库存位置、制作和配送归门店。一个员工可承担多个职责。线下收款、明显降级替代、较大改价、库存调整等需要对应权限；负责人分配是可选操作。首版支持自提和门店安排配送，配送失败记录原因并支持重排或售后，不自动恢复成品物料。每日及时段产能先预警，授权人员可决定超量接单；不要求花艺师排班。今日工作台集中展示缺料、采购延期、待客户确认、制作逾时及配送异常。

## 10. 跨流程校验与待试用问题

1. 待支付能力锁定与批次预留必须分别建模，避免重复扣减；过期、取消、支付回调重试应幂等。
2. “已付款”和“供应已保障”分别展示。支付成功后若无法预留，保留订单并进入缺料风险和处理流程，不能伪称可制作。
3. 自动制作结转仅在可识别计划批次且库存足够时执行。实物不符、批次不明或数量不足进入快速异常处理，保留原库存事实。
4. 整卷耗材的门店费用与每件预计成本属于两种分析口径；利润报表须明确避免重复相加。
5. 真正卡住履约的条件限于无法作出可靠供应承诺、客户可感知变更未经确认或库存结转不可信。任务分配、常规领料、逐项确认、照片和排班不构成默认前置条件。
6. 真实试用重点观察：待支付超时及并发、缺料预约、降级验收、订单变更与制作并发、直接完成制作、返工、退款、最终采购成本补录。根据试用结果修订流程。

## 11. 下一步建模清单

据此设计 Prisma Schema 时优先明确：租户和门店外键、物料等级与单位、配方版本快照、订单多维状态、临时能力锁定、正式物料需求、批次预留、采购需求分配、分次验收与降级、位置和库存流水、制作差异、损耗及成本调整。金额和数量使用定点数；业务唯一编码按租户或门店设复合约束。Schema 评审后再实现核心服务。

## 12. 已确认的库存边界补充

1. 预约订单依赖的已确认在途供应必须有数量分配记录，不能被多个订单重复承诺；尚未获供应商确认的采购建议不算供应保障。
2. 待支付锁定依据配方展开后的关键物料需求计算，不仅锁 SKU 件数。锁定有截止时间；支付成功时在同一事务中释放临时锁定并创建正式预留，避免共享花材超卖。
3. 盘点实数少于已预留量时保留盘点事实，标记受影响订单风险，由员工重新分配或补购。调整须留原因与复核信息，不静默覆盖预留。
4. 打样拆解花材在计划内部可模拟复用；实物进入普通可售库存前必须重新验收等级与最晚可用时间。未验收部分不能被顾客订单使用。
5. 整卷耗材在制作区区分未开封与在用；用尽时快速确认整卷消耗，定期盘点，不逐单计量或归属订单。
6. 批次成本可以暂估并显式标记；最终价格、折价及运费确认后形成最终成本。已结账订单通过成本调整留痕，原快照不覆盖。
7. 打样计划批准时重新检查现货，只预留首次制作所需花材。后续步骤预期从拆解获得的花材仅作计划预测，不作为现有可用库存或已保障供应。
8. 每次拆解后以实际可复用数量重算剩余步骤。低于预测时提示补购、调整顺序或缩减计划，不能自动延续旧承诺。
9. 已确认顾客订单的批次预留优先于尚未开始的打样计划；发生竞争时标记打样风险，由员工决定改期或补购，不挪用顾客订单预留。
10. 打样无需单独的“领用”按钮。员工开始制作时系统自动记录操作人并执行首次预留花材的位置流转；若直接完成，系统补齐可验证的默认流转。库存不足或批次不明时才进入异常处理。
11. 样品制作后预计可复用量仍只是预测。拆解时员工确认实际物料、等级和数量，之后才可用于下一步打样，并重新计算余下计划。
12. 打样中途暂停或取消时自动释放未领用的预留；已进入制作区的花材由员工快速确认可回库、继续留用或报损的数量。系统记录这些事实，不自动假设花材完好。
13. 样品完成后继续留在样品库；转为可售 SKU 须由员工主动发起，补齐价格、规格与配方并通过上架检查。一个商品可包含来自多个样品的 SKU；同一样品也可生成多个 SKU。每个 SKU 可独立增加花材数量、变更花材或包材颜色，拥有自己的价格与配方。样品清单只作为新 SKU 草稿配方的起点，后续修改样品不自动改动 SKU 配方；调整某个 SKU 也不影响其他 SKU。
14. 拆解后由员工确认实际可用的物料、等级和数量；系统记录来源样品、拆解时间并检查最晚可用时间。顾客订单预留与打样批准并发时，由数据库事务防止同批次重复分配；已有顾客订单预留优先，打样冲突时重算。
15. 交付完成后自动生成订单结账成本快照。尚未最终确认的采购或配送费用标为暂估，最终确定后以成本调整记录差额，不覆盖原快照。
