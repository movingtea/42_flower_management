# Flower Studio 2.0 第一阶段真实门店试用清单

## 目标

由真实花店员工在日常操作节奏下验证第一阶段是否减少工作量，并记录任何卡点。测试数据可以删除，不要求迁移旧数据。

## 建议参与角色

- 一名负责录单或店务的员工
- 一名负责采购或验收的员工
- 一名实际制作花束的花艺师

同一人可以承担多个角色，不要求先分配制作任务。

## 必测场景

- [ ] 创建包含两个不同 SKU 的后台订单，确认后自动生成物料需求和制作待办。
- [ ] 库存充足时直接一键完成制作，不填写领料或逐项用量。
- [ ] 两个 SKU 共用同一批次时，分别登记实际用量、损耗或退料并完成制作。
- [ ] 库存不足时保留订单，创建采购单并把采购行关联到具体缺料需求。
- [ ] 分次验收入库后，确认关联订单优先重检，且采购行已入库数量不会再次被分配。
- [ ] 用低等级、不同颜色或不同规格物料替代缺料；确认系统要求原因及客户确认，并保留原需求历史。
- [ ] 制作前修改各 SKU 数量或交付时间；确认新预留原子更新，失败时原方案不变。
- [ ] 记录线下收款、部分退款和最终批次成本；确认原支付与结账快照未被覆盖。
- [ ] 完成交付，核对收入、材料、损耗、耗材、人工和配送成本快照。

## 观察重点

- 正常订单是否只需要录单、确认、制作完成和交付完成等少量操作。
- 缺料、替代、损耗等例外是否在需要时才展开。
- 页面用语是否符合花店员工的日常说法。
- 是否出现员工必须为了推动状态而做无业务意义的点击。
- 手机或门店常用电脑上的表单是否容易操作。

## 记录格式

每个问题记录：发生时间、操作角色、订单号、当时要完成的事情、卡住的位置、员工期望的操作方式，以及是否阻断营业。

处理原则：系统能够根据既有数据生成的标识不得要求门店员工手工编制；已经具备底层能力但试用人员无法发现的操作，仍按未达到试用要求处理，不能仅以“功能存在”关闭问题。

## 通过标准

- 正常库存订单无需任务分配或逐项领料即可完成。
- 库存、预留、损耗和成本结果与实际操作一致，不出现负库存或重复扣减。
- 例外流程可以完成且历史可追溯。
- 没有阻断录单、制作或交付的高优先级问题。
- V1 WMS 中未被明确替代、合并或废弃的功能均已迁移至 V2，并通过逐项回归；CMS、CRM 和小程序不属于第一阶段关闭范围。
- V2 WMS 延续 V1 的整体视觉样式、导航结构、页面密度和主要交互习惯，试用人员无需适应一套完全不同的仓储与履约后台界面。
- 登录、角色权限、异常提示、审计、数据约束、备份恢复、构建部署和基本性能达到正式上线要求。
- 用户无需返回 V1 即可完成全部 WMS 正常业务，V2 WMS 可以作为正式入口投入使用；尚未迁移的 CMS、CRM 和小程序继续使用原入口。

以上条件必须全部满足，才可宣布第一阶段结束并将 V2 提交上线。
